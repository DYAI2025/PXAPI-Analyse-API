## D. What this slice delivers

### The problem it solves

Before this slice `src/pxapi/` held exactly one executable module. PXAPI had a contract
foundation and had never fetched a website. PXK-67 is the first vertical product path.

### The real request path

```text
POST /v1/analysis-runs            adapters/inbound/http_api.py     FastAPI: transport only
  -> json.loads, rejecting NaN/Infinity
  -> registry.validate("analysis-run-request")   JSON Schema is the only contract authority
       violations -> to_problem() -> 422 problem.v1.json
  -> application/analyze_homepage.py             the single use case, one lifecycle
       |- domain/run_state.transition()          CREATED -> QUEUED -> RUNNING -> SUCCEEDED|FAILED
       |- adapters/web/target_policy.py          public-target boundary, before any socket
       |- adapters/web/page_fetcher.py           real HTTP, address-pinned, manual redirects
       |- adapters/web/html_observations.py      stdlib HTMLParser
       \- mapping -> MeasurementRecord + WebsiteEvidence
  -> registry.validate(...) on every produced document
  -> 200 canonical envelope
```

`adapters/inbound/cli.py` drives the same use case through the same composition root, which is
what the real-boundary smoke uses.

### The canonical response

`analysis-run-state` is a closed root and cannot embed stage executions, so the envelope is a
thin transport composition whose parts each validate independently:

```text
analysis_run_request   analysis-run-request.v1.json
analysis_run_state     analysis-run-state.v1.json
stage_executions[]     stage-execution-record.v1.json
measurements[]         measurement-record.v1.json
website_evidence[]     website-evidence.v1.json
```

The envelope is deliberately **not** a registered contract. It adds no analysis meaning, and
registering it would create a second authority beside the contracts it merely carries.

### No contract needed changing

`metric_id`, `collector`, `scenario` and `stage_id` all `$ref` `common#/$defs/code` — open
vocabularies that fix a token's lexical shape and never the set. Every metric this slice
introduces validates against the contracts exactly as merged. `contracts/v1/manifest.json`
gained three `problem_codes` and nothing else; `git diff -U0` reports **0 deletions** in it.

### Truth policy

| Situation | Measurement | Evidence | Run |
| --- | --- | --- | --- |
| Value observed | `KNOWN` + typed `result` | `KNOWN`, no polarity | `SUCCEEDED` |
| Timeout | `TIMEOUT`, no result | polarity refused | `FAILED` |
| DNS / connection failure | `PROVIDER_FAILURE` | refused | `FAILED` |
| Blocked target | `PERMISSION_DENIED` | refused | `FAILED` |
| Parser failure | `RUNTIME_ERROR` (document metrics only) | refused | `SUCCEEDED` |
| Undecodable content encoding | `RUNTIME_ERROR` (document metrics only) | refused | `SUCCEEDED` |
| HTTP 4xx/5xx | status `KNOWN` | `KNOWN`, no polarity | `SUCCEEDED` |
| Element absent | presence `KNOWN false`; value `NOT_APPLICABLE` | `KNOWN`, no polarity | `SUCCEEDED` |
| Non-HTML response | document metrics `NOT_APPLICABLE` | no polarity | `SUCCEEDED` |
| Text over the contract bound | presence `KNOWN`; value `UNKNOWN`, no result | refused | `SUCCEEDED` |
| Body hit the byte bound | not-found elements `UNKNOWN`, never `false` | refused | `SUCCEEDED` |

Three states are kept apart that are easy to conflate: **absent** is a fact about the site,
**not applicable** a fact about the measurement, **unknown** an assessment that established
nothing. No evidence document in any path carries a polarity — every fact here is an
observation, and inventing a good/bad verdict is what the contract's optional polarity avoids.

The `single_line_text` bound is **read out of the schema** at runtime
(`ContractRegistry.max_single_line_text()`, mirroring the existing `max_problem_errors()`), so
no collector holds a copy of the number that could disagree with the contract.

### Public-target boundary

Decided before any socket exists, and again on every redirect hop:

1. `http` and `https` only.
2. Credentials in the authority refused, and never rendered into a message or a log.
3. Hostname resolved; an IP literal skips resolution but never classification.
4. Every address classified: `is_global`, not multicast, not reserved. IPv4-mapped IPv6 is
   unwrapped first, so `::ffff:127.0.0.1` cannot pass as globally routable.
5. **Partial resolution is fatal** — one forbidden address condemns the host.
6. The connection is made to the **validated address**, not the hostname, so a name cannot be
   rebound between the check and the connect. TLS still verifies the certificate against the
   hostname.
7. Redirects are followed by hand; each `Location` is re-validated and re-resolved.

Bounds: 3 redirect hops, 5 s connect, 10 s read, 20 s overall deadline, 2 MiB response. The
read is bounded, and decompression is bounded to the same figure, so a compression bomb cannot
inflate past one bounded body.

The shipped `PublicTargetPolicy` takes **no argument that could widen its address rule**. The
single extension point is a method, so the loopback policy the integration tests need is a
subclass defined in `tests/`, and a test asserts both that the shipped policy still refuses
every loopback address and that its constructor has gained no such parameter.

### The dependency guard was narrowed, not dropped

Runtime validation makes PXK-59's blanket rule untrue, so it is narrowed in the manner of
PXK-60's behavior gate. `domain`, `ports`, `application` and `config` may still never import a
validator — that is the invariant that keeps contract shapes out of business logic. Exactly one
allowlisted adapter may, and an allowlist entry that is stale, unearned or outside `adapters`
fails on its own. `tests/architecture/boundaries.py` needed no change: `adapters` was already
in `THIRD_PARTY_ALLOWED`, and the AC3 ban on `fastapi` only binds outside adapters.

`tests/contracts/support.py` now builds on the runtime registry instead of restating it, so the
validation the tests exercise is the code the service runs. It lost 178 lines of duplication.

## G. Blockers and follow-ups discovered

1. **The first smoke found a real defect, and it was the defect this slice exists to prevent.**
   python.org returns gzip whatever `Accept-Encoding` asks for. The parser received compressed
   bytes, found no `<title>`, and the run reported that the *site* had no title, description or
   canonical link. Fixed in `c205f81`: gzip and deflate are decoded, and an encoding we cannot
   decode is recorded as a runtime error of ours rather than as an absent element. This is the
   strongest argument in this document for keeping the live smoke a delivery requirement —
   1,092 passing offline tests did not catch it.
2. **The reviewability figure is over the convention.** See section E; a Product Owner decision.
3. **Packaging.** `contracts/v1/` sits outside the wheel's `src/pxapi` package. The runtime
   locates it by path with a `PXAPI_CONTRACTS_DIR` override. Packaging the registry into a
   distributable artifact is deliberately deferred; deployment is out of scope.
4. **`brotli` and `zstd` responses are not decodable** and are reported as such. Whether to add
   a decoder is a product decision, not an implementation convenience.
5. **Evidence is currently one document per measurement.** That establishes the referencing
   chain honestly but adds no information over the measurements. Whether evidence should
   aggregate is a decision for the slice that first needs a judgement.

## H. Deliberately deferred

Whether a failed stage is fatal to a run stays orchestration policy, exactly as PXK-60 left it:
this slice fails the run when nothing could be fetched and succeeds it when the transport facts
were obtained, and no contract decides that for it. `not_assessed_reason` still carries no
severity and no retry policy.
